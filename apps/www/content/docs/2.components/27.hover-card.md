::fw
#vue
`GoopHoverCard` wraps the same [reka-ui Hover Card](https://reka-ui.com/docs/components/hover-card) primitive as shadcn-vue's HoverCard, with the same API. Open and close delays, keyboard focus, touch handling, and positioning work the same. Swap the imports and you're done.

#react
`GoopHoverCard` wraps the same [Radix Hover Card](https://www.radix-ui.com/primitives/docs/components/hover-card) primitive as shadcn/ui's HoverCard, with the same API and classes. Open and close delays, keyboard focus, touch handling, and positioning work the same. Swap the imports and you're done.
::

## Installation

::fw{when="vue"}
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopHoverCard*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```
::

::fw{when="react"}
```bash
pnpm add @goopui/react
```

```css [app/globals.css]
@import "tailwindcss";
@import "@goopui/react/goop.css";
```

That one line adds the styles and points Tailwind at the component classes. It works the same in Next.js and Vite; see [Installation](/docs/getting-started/installation#nextjs). It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--radius`).
::

## Usage

::fw
#vue
```vue
<script setup lang="ts">
// Nuxt auto-imports these. In plain Vue, import them:
import { GoopHoverCard, GoopHoverCardContent, GoopHoverCardTrigger } from '@goopui/vue'
</script>

<template>
  <GoopHoverCard :open-delay="200">
    <GoopHoverCardTrigger href="https://nuxt.com" class="underline underline-offset-4">
      @nuxt
    </GoopHoverCardTrigger>
    <GoopHoverCardContent>
      <p class="text-sm font-semibold">@nuxt</p>
      <p class="text-sm">The intuitive Vue framework.</p>
    </GoopHoverCardContent>
  </GoopHoverCard>
</template>
```

#react
```tsx
import { GoopHoverCard, GoopHoverCardContent, GoopHoverCardTrigger } from '@goopui/react'

export function NextjsCard() {
  return (
    <GoopHoverCard openDelay={200}>
      <GoopHoverCardTrigger href="https://nextjs.org" className="underline underline-offset-4">
        @nextjs
      </GoopHoverCardTrigger>
      <GoopHoverCardContent>
        <p className="text-sm font-semibold">@nextjs</p>
        <p className="text-sm">The React Framework, created and maintained by @vercel.</p>
      </GoopHoverCardContent>
    </GoopHoverCard>
  )
}
```
::

The parts are `GoopHoverCard`, `GoopHoverCardTrigger`, and `GoopHoverCardContent`. All the goo lives on `GoopHoverCardContent`.

## Behavior

- **Bloom from the trigger.** The card pools from a droplet on its edge facing the link, spreads out with a lobed edge, overshoots, and wobbles to rest (`wobble`, `openSlosh`). Then it splashes a few drops all around, kept off the link (`openDrips`).
- **Close.** The card pulls in, wobbles, and shrinks back into the edge it grew from (`closeSlosh`).
- **Content stays sharp.** The card's background, ring, and shadow are drawn on an `aria-hidden` surface behind the content, so the text is never filtered. The content fades in once the goo settles (`fade`).

## Bloom origin

`bloomFrom` picks where the bloom starts: `'trigger'` (the default, the card's edge facing its link) or `'center'` (the card's own center, like Popover).

::preview{:controls="false"}
:demo-hover-card{set="from"}
::

::fw
#vue
```vue
<GoopHoverCardContent>...</GoopHoverCardContent>                     <!-- from the edge facing the link -->
<GoopHoverCardContent bloom-from="center">...</GoopHoverCardContent> <!-- from its center -->
```

#react
```tsx
<GoopHoverCardContent>...</GoopHoverCardContent> {/* from the edge facing the link */}
<GoopHoverCardContent bloomFrom="center">...</GoopHoverCardContent> {/* from its center */}
```
::

## Surface color

A hover card's trigger is usually a link with no background, so the card defaults to `surface="popover"`: shadcn's popover tokens. `'trigger'` takes the trigger's colors, and any CSS color works too.

## Turning parts off

Every effect is its own toggle, and they all default to on:

::fw
#vue
```vue
<GoopHoverCardContent :open-drips="false">...</GoopHoverCardContent>  <!-- no splash -->
<GoopHoverCardContent :wobble="false">...</GoopHoverCardContent>      <!-- no overshoot -->
<GoopHoverCardContent :close-slosh="false">...</GoopHoverCardContent> <!-- a plain shrink on close -->
```

#react
```tsx
<GoopHoverCardContent openDrips={false}>...</GoopHoverCardContent> {/* no splash */}
<GoopHoverCardContent wobble={false}>...</GoopHoverCardContent> {/* no overshoot */}
<GoopHoverCardContent closeSlosh={false}>...</GoopHoverCardContent> {/* a plain shrink on close */}
```
::

::fw
#vue
`:goo="false"` renders exactly shadcn's `HoverCardContent`, with its own enter and exit animation.

#react
`goo={false}` renders exactly shadcn's `HoverCardContent`, with its own enter and exit animation.
::

## Driving it from code

::fw
#vue
`GoopHoverCardContent` exposes its engine handle as `handle` (`null` before it mounts, or when `goo` is off). The card only exists while open.

#react
`GoopHoverCardContent`'s `goopRef` receives its engine handle (`null` before it mounts, or when `goo` is off). The card only exists while open; `ref` is the card element, as in shadcn/ui.
::

## Props

::fw
#vue
The root and trigger take shadcn-vue's props (`openDelay`, `closeDelay`, `asChild`, ...). `GoopHoverCardContent` takes reka-ui's `HoverCardContent` props (`side`, `align`, `sideOffset`, and the rest), `class`, and these goo props. Defaults are `align="center"` and `sideOffset` 4.

#react
The root and trigger take shadcn/ui's props (`openDelay`, `closeDelay`, `asChild`, ...). `GoopHoverCardContent` takes Radix's `HoverCardContent` props (`side`, `align`, `sideOffset`, and the rest), `className`, `goopRef`, and these goo props. Defaults are `align="center"` and `sideOffset={4}`.
::

## Accessibility

::fw
#vue
Focus handling and dismissal come from reka-ui; like shadcn's, a hover card is for sighted mouse and keyboard users and its content shouldn't be the only way to reach information. The goo surface is `aria-hidden` and can't be clicked, and the content is never filtered. Under reduced motion the card opens and closes plainly: it keeps its goo shape and color, but the bloom, slosh, and splash are off. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#react
Focus handling and dismissal come from Radix; like shadcn's, a hover card is for sighted mouse and keyboard users and its content shouldn't be the only way to reach information. The goo surface is `aria-hidden` and can't be clicked, and the content is never filtered. Under reduced motion the card opens and closes plainly: it keeps its goo shape and color, but the bloom, slosh, and splash are off. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

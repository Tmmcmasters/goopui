#vue
`GoopTooltip` wraps the same [reka-ui Tooltip](https://reka-ui.com/docs/components/tooltip) primitive as shadcn-vue's Tooltip, with the same API. Delays, hover and focus handling, and positioning work the same. Swap the imports and you're done.

#react
`GoopTooltip` wraps the same [Radix Tooltip](https://www.radix-ui.com/primitives/docs/components/tooltip) primitive as shadcn/ui's Tooltip, with the same API and classes. Delays, hover and focus handling, and positioning work the same. Swap the imports and you're done.

## Installation

::fw{when="vue"}
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopTooltip*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--foreground`, `--background`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```
::

::fw{when="react"}
```bash
pnpm add @goopui/react
```

```css [app/globals.css]
@import "tailwindcss";
@import "@goopui/react/goop.css";
```

That one line adds the styles and points Tailwind at the component classes. It works the same in Next.js and Vite; see [Installation](/docs/getting-started/installation#nextjs). It needs Tailwind CSS v4 and the shadcn tokens (`--foreground`, `--background`, `--radius`).
::

## Usage

::fw
#vue
Wrap your app (or the part that has tooltips) in a `GoopTooltipProvider` once. It sets `delayDuration` to 0, like shadcn.

#react
Wrap your app (or the part that has tooltips) in a `GoopTooltipProvider` once. It is shadcn/ui's `TooltipProvider`, with `delayDuration` set to 0.
::

::fw
#vue
```vue
<script setup lang="ts">
// Nuxt auto-imports these. In plain Vue, import them:
import { GoopButton, GoopTooltip, GoopTooltipContent, GoopTooltipProvider, GoopTooltipTrigger } from '@goopui/vue'
</script>

<template>
  <GoopTooltipProvider>
    <GoopTooltip>
      <GoopTooltipTrigger as-child>
        <GoopButton variant="outline">Hover me</GoopButton>
      </GoopTooltipTrigger>
      <GoopTooltipContent>Add to library</GoopTooltipContent>
    </GoopTooltip>
  </GoopTooltipProvider>
</template>
```

#react
```tsx
import { GoopButton, GoopTooltip, GoopTooltipContent, GoopTooltipProvider, GoopTooltipTrigger } from '@goopui/react'

export function AddToLibrary() {
  return (
    <GoopTooltipProvider>
      <GoopTooltip>
        <GoopTooltipTrigger asChild>
          <GoopButton variant="outline">Hover me</GoopButton>
        </GoopTooltipTrigger>
        <GoopTooltipContent>Add to library</GoopTooltipContent>
      </GoopTooltip>
    </GoopTooltipProvider>
  )
}
```
::

The parts are `GoopTooltipProvider`, `GoopTooltip`, `GoopTooltipTrigger`, and `GoopTooltipContent`. All the goo lives on `GoopTooltipContent`.

## Behavior

It's the [Popover](/docs/components/popover)'s emerge engine, scaled down for a small label:

- **Open (bloom).** The label pools from its own center, spreads out with a lobed edge, overshoots, and settles. It's quick: about a third of a second at the default preset.
- **Light slosh.** The edges bulge a little and settle (`openSlosh`, 0.4 strength by default).
- **Light splash.** A few small drops fly off and keep clear of the trigger. It's much lighter than the Popover's (`openDrips`, and the `openDrip*` knobs to turn it up).
- **Close.** The label pulls in with a light wobble (`closeSlosh`, 0.5) and shrinks back to its center.
- **Text stays sharp.** Only the background is goo, drawn behind the label.

::fw
#vue
`flowStyle="neck"` runs it out of the trigger through a neck instead. `:flow="false"` gives the older open: a small bulb swells out of the trigger edge, the label inflates out of it, and the neck snaps. That open has no drips unless you turn `openDrips` on.

#react
`flowStyle="neck"` runs it out of the trigger through a neck instead. `flow={false}` gives the older open: a small bulb swells out of the trigger edge, the label inflates out of it, and the neck snaps. That open has no drips unless you turn `openDrips` on.
::

## Inverted tokens

Like shadcn's tooltip, it's inverted: a `--foreground` background with `--background` text. That is the default here too, and the arrow matches. A tooltip is a label, not an extension of its trigger, so unlike the Popover the default `surface` is `'popover'` (shadcn's inverted look), not `'trigger'`.

## Surface color and drips

Set `surface="trigger"` to use the trigger's background and text color, or pass any CSS color. The text and the arrow follow. `openDrips` sets the splash:

::preview{:controls="false"}
:demo-tooltip{set="surface"}
::

::fw
#vue
```vue
<GoopTooltipContent surface="trigger">Takes the trigger's color</GoopTooltipContent>
<GoopTooltipContent surface="oklch(0.62 0.19 150)">Any CSS color</GoopTooltipContent>
<GoopTooltipContent :open-drips="false">No splash</GoopTooltipContent>
<GoopTooltipContent :open-drips="1.5">A bigger splash</GoopTooltipContent>
```

#react

## Driving it from code

::fw
#vue
`GoopTooltipContent` exposes its engine handle as `handle` (`null` before it mounts, or when `goo` is off).

#react
`GoopTooltipContent`'s `goopRef` receives its engine handle (`null` before it mounts, or when `goo` is off). `ref` is the tooltip element, as in shadcn/ui.
::

## Props

::fw
#vue
`GoopTooltipProvider`, `GoopTooltip`, and `GoopTooltipTrigger` take shadcn-vue's props. `GoopTooltipContent` takes reka-ui's `TooltipContent` props (`side`, `align`, `sideOffset`, ...), `class`, and these goo props. `sideOffset` defaults to 0, like shadcn.

#react
`GoopTooltipProvider`, `GoopTooltip`, and `GoopTooltipTrigger` take shadcn/ui's props. `GoopTooltipContent` takes Radix's `TooltipContent` props (`side`, `align`, `sideOffset`, ...), `className`, `goopRef`, and these goo props. `sideOffset` defaults to 0, like shadcn.
::

## Accessibility

::fw
#vue
Hover and keyboard focus open it, Escape closes it, and the content has `role="tooltip"` and is linked to the trigger, all from reka-ui. The goo surface is `aria-hidden`. Under reduced motion the tooltip opens and closes plainly: it keeps its goo shape and color, with no bloom, bridge, slosh, drops, or wobble. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#react
Hover and keyboard focus open it, Escape closes it, and the content has `role="tooltip"` and is linked to the trigger, all from Radix. The goo surface is `aria-hidden`. Under reduced motion the tooltip opens and closes plainly: it keeps its goo shape and color, with no bloom, bridge, slosh, drops, or wobble. See [Accessibility & reduced motion](/docs/getting-started/accessibility).
::

The goo comes in from one edge with a wobbly front of low, wide mounds that are different every time. The front leads with a little momentum, the screen stays covered until the new page has rendered, and then the wall drains out the far edge, its trailing edge stretching back like poured goo. Nothing is left behind.

## Nuxt

Turn it on in the module options. It's off by default.

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
  goop: {
    pageTransition: true,
    // or: pageTransition: { direction: 'up', duration: 500 },
  },
})
```

Before each route change, navigation waits for the goo to cover the screen. The reveal starts on `page:finish`, once the new page has rendered. If that never fires, it reveals after `timeout` ms (default 2000). Hash and query changes don't transition, and neither does the first load. The live handle is `useNuxtApp().$goopPageTransition`.

## Vue

With vue-router, pass the router to `GoopPageTransition` once, near the root:

```vue
<script setup lang="ts">
import { GoopPageTransition } from '@goopui/vue'
import { useRouter } from 'vue-router'

const router = useRouter()
</script>

<template>
  <GoopPageTransition :router="router" direction="down" />
  <RouterView />
</template>
```

Or drive it yourself with the composable. `cover()` resolves once the screen is covered, and `reveal()` resolves once it's gone:

```ts
import { useGoopPageTransition } from '@goopui/vue'

const goo = useGoopPageTransition({ direction: 'left' })

async function swap() {
  await goo.cover()
  await loadTheNextThing()
  await goo.reveal()
}
```

## Core

Without a framework, use `createPageTransition` from `@goopui/core`. It returns `{ cover, reveal, phase, update, destroy }`:

```ts
import { createPageTransition } from '@goopui/core'

const goo = createPageTransition({ direction: 'down' })
await goo.cover()
// swap the page
await goo.reveal()
```

## Colors

The wall reads `--goop-page-transition`, which falls back to `--primary`. Set `--goop-page-transition-accent` to give the moving edges a thin colored lip. This site uses ink with a Slime lip:

```css
:root {
  --goop-page-transition: oklch(0.2 0.012 60);
  --goop-page-transition-accent: #1fa64a;
}
.dark {
  --goop-page-transition: oklch(0.11 0.008 60);
}
```

The `color` and `accent` options override both. They take any CSS color or `var()`, and `accent: false` turns the lip off.

## Options

| Option | Default | |
| --- | --- | --- |
| `direction` | `'down'` | Which way the goo travels: `'down'`, `'up'`, `'left'` or `'right'`. |
| `duration` | `600` | Total cover and reveal time in ms. The hold in between lasts until the page is ready. |
| `coverDuration`, `revealDuration` | | Set each part separately (ms). |
| `bulge` | `true` | Mounds on the front. `false` gives a flat front, and a number from 0 to 2 scales them. |
| `wobble` | `true` | The mounds wobble and drift as they move. |
| `lag` | `true` | The trailing edge stretches back as it drains. |
| `preset` | `'playful'` | `'subtle'`, `'playful'` or `'wild'`. |
| `speed` | `1` | Speed multiplier. |
| `color`, `accent` | CSS variables | See [Colors](#colors). |
| `zIndex` | `2147483000` | The overlay's z-index. |

In Vue they're props on `GoopPageTransition` and options to `useGoopPageTransition`, and `goo: false` turns it off. In core, use `enabled: false` for the same thing.

## Performance

The overlay is one fixed, full-screen SVG with one filled path, plus one more for the lip. Each frame rewrites that path from about 60 points. There's no blur filter, canvas, or WebGL, so it's cheap on phones. Being `position: fixed`, it never changes the page's scroll size, and nothing is in the DOM until the first transition.

## Accessibility

The overlay is `aria-hidden`. It blocks clicks while it covers the screen, so a double click can't start two navigations, and lets them through while it drains. Focus and scroll are left to the router.

Under reduced motion there's no goo. The screen fades to the wall color and back in about 150 ms each way. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

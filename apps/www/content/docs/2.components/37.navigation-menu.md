::fw
#vue
`GoopNavigationMenu` wraps the same [reka-ui Navigation Menu](https://reka-ui.com/docs/components/navigation-menu) primitive as shadcn-vue's NavigationMenu, with the same parts and API: `GoopNavigationMenuList`, `Item`, `Trigger`, `Content`, `Link`, `Indicator`, `Viewport`, and `navigationMenuTriggerStyle`. Hover and click opening, delays, keyboard navigation, and `asChild` work the same. Swap the imports and you're done.

#react
`GoopNavigationMenu` wraps the same [Radix Navigation Menu](https://www.radix-ui.com/primitives/docs/components/navigation-menu) primitive (from the `radix-ui` package) as shadcn/ui's NavigationMenu, with the same parts and API: `GoopNavigationMenuList`, `Item`, `Trigger`, `Content`, `Link`, `Indicator`, `Viewport`, and `navigationMenuTriggerStyle`. Hover and click opening, delays, keyboard navigation, and `asChild` work the same. Swap the imports and you're done.
::

## Installation

::fw{when="vue"}
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopNavigationMenu*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--muted`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```
::

::fw{when="react"}
Install `@goopui/react` and add its stylesheet as shown on the [Installation](/docs/getting-started/installation#nextjs) page, then import the parts from `@goopui/react`. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--muted`, `--radius`).
::

## Usage

::fw
#vue
```vue
<script setup lang="ts">
// Nuxt auto-imports the components. In plain Vue, import them:
import {
  GoopNavigationMenu,
  GoopNavigationMenuContent,
  GoopNavigationMenuItem,
  GoopNavigationMenuLink,
  GoopNavigationMenuList,
  GoopNavigationMenuTrigger,
  navigationMenuTriggerStyle,
} from '@goopui/vue'
</script>

<template>
  <GoopNavigationMenu>
    <GoopNavigationMenuList>
      <GoopNavigationMenuItem>
        <GoopNavigationMenuTrigger>Getting started</GoopNavigationMenuTrigger>
        <GoopNavigationMenuContent>
          <ul class="grid w-72 gap-1 p-1">
            <li>
              <GoopNavigationMenuLink href="/docs" class="flex-col items-start gap-1">
                <div class="text-sm font-medium">Introduction</div>
                <p class="text-sm text-muted-foreground">Components that drip.</p>
              </GoopNavigationMenuLink>
            </li>
          </ul>
        </GoopNavigationMenuContent>
      </GoopNavigationMenuItem>
      <GoopNavigationMenuItem>
        <GoopNavigationMenuLink href="/docs" :class="navigationMenuTriggerStyle()">
          Docs
        </GoopNavigationMenuLink>
      </GoopNavigationMenuItem>
    </GoopNavigationMenuList>
  </GoopNavigationMenu>
</template>
```

#react
```tsx

  GoopNavigationMenuTrigger,
  navigationMenuTriggerStyle,

export function SiteNav() {
  return (

      <GoopNavigationMenuList>
        <GoopNavigationMenuItem>

  )
}
```

All the goo props go on `GoopNavigationMenu`, which shares them with its parts. Like shadcn's, the root renders the shared viewport for you (`viewport`, default `true`).

## Behavior

- **One highlight.** The hover and open background of the top-level triggers and links is a single goo blob. It flows to whichever item you point at (or focus with the keyboard), stretching into a tail with fat neck lumps while it travels and landing with a jelly bounce (`highlight`, `momentum`, `wobble`). While a panel is open it rests on that panel's trigger.
- **Bloom from the trigger.** The panel pools from a droplet under the active trigger, spreads with a lobed edge, overshoots, and settles (`bloom`, `openSlosh`), with a light splash of drops kept off the menu bar (`openDrips`). On close it pulls in and shrinks back into the trigger (`closeSlosh`).
- **One body between triggers.** Move to another trigger while a panel is open and the panel does not close and re-open: it slides under the new trigger and resizes to the new content as one goo body, settling with a gentle jelly wobble (`jelly`). shadcn's content slide plays inside it.
- **Links inside a panel** get their own goo highlight with the menu's feel (`contentHighlight`).
- **Content stays sharp.** The panel's background, ring, and shadow are drawn on an `aria-hidden` surface behind the content, so the text is never filtered. The content fades in once the goo settles (`fade`).

## Without the viewport

::fw
#vue
With `:viewport="false"` each panel renders under its own trigger, as in shadcn. Each one blooms out of its trigger and shrinks back into it; there is no shared body to slide.

#react
With `viewport={false}` each panel renders under its own trigger, as in shadcn. Each one blooms out of its trigger and shrinks back into it; there is no shared body to slide.
::

#vue
```vue
<GoopNavigationMenu :viewport="false">...</GoopNavigationMenu>
```

#react
```tsx
<GoopNavigationMenu viewport={false}>...</GoopNavigationMenu>
```

## Turning parts off

Every effect is its own toggle, and they all default to on:

::fw
#vue
```vue
<GoopNavigationMenu :jelly="false">...</GoopNavigationMenu>      <!-- the panel jumps to each new size -->
<GoopNavigationMenu :open-drips="false">...</GoopNavigationMenu> <!-- no splash -->
<GoopNavigationMenu :bloom="false">...</GoopNavigationMenu>      <!-- shadcn's panel, goo highlight only -->
<GoopNavigationMenu :highlight="false">...</GoopNavigationMenu>  <!-- shadcn's flat hover background -->
```

`:goo="false"` renders exactly shadcn's `NavigationMenu`.

#react
```tsx
<GoopNavigationMenu jelly={false}>...</GoopNavigationMenu>      {/* the panel jumps to each new size */}
<GoopNavigationMenu openDrips={false}>...</GoopNavigationMenu>  {/* no splash */}
<GoopNavigationMenu bloom={false}>...</GoopNavigationMenu>      {/* shadcn's panel, goo highlight only */}
<GoopNavigationMenu highlight={false}>...</GoopNavigationMenu>  {/* shadcn's flat hover background */}
```

`goo={false}` renders exactly shadcn's `NavigationMenu`.

## Props

::fw
#vue
The root takes reka-ui's `NavigationMenuRoot` props (`modelValue`, `delayDuration`, `orientation`, ...), shadcn's `viewport`, `class`, `sound`, and these goo props. The other parts take shadcn-vue's props (`class`, `asChild`, ...).

#react
The root takes Radix's `NavigationMenu.Root` props (`value`, `onValueChange`, `delayDuration`, `orientation`, ...), shadcn's `viewport`, `className`, `sound`, and these goo props. The other parts take shadcn/ui's props (`className`, `asChild`, ...). `ref` is always the DOM node. The engine handles come through `goopRef` on the parts that own them: `GoopNavigationMenuList` (the highlight handle) and `GoopNavigationMenuContent` (its link highlight). With `viewport={false}`, `GoopNavigationMenuContent` also takes `bloomRef`, which receives the panel's own bloom handle.

## Accessibility

::fw
#vue
Keyboard navigation, focus management, and dismissal come from reka-ui.

#react
Keyboard navigation, focus management, and dismissal come from Radix.
::

The highlight follows keyboard focus as well as the pointer. The goo highlight and the panel's goo surface are `aria-hidden` and can't be clicked, and the content is never filtered. Under reduced motion the goo is static: the highlight and the panel snap into place with their goo shape and color, but the travel, bloom, jelly, slosh, and splash are off. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#vue
`GoopContextMenu` wraps the same [reka-ui Context Menu](https://reka-ui.com/docs/components/context-menu) primitive as shadcn-vue's ContextMenu, with the same API. Right-click and long-press, keyboard navigation, typeahead, focus handling, and positioning work the same. Swap the imports and you're done.

#react
`GoopContextMenu` wraps the same [Radix Context Menu](https://www.radix-ui.com/primitives/docs/components/context-menu) primitive (from the `radix-ui` package) as shadcn/ui's ContextMenu, with the same API. Right-click and long-press, keyboard navigation, typeahead, focus handling, and positioning work the same. Swap the imports and you're done.
::

## Installation

::fw{when="vue"}
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopContextMenu*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--accent`, `--destructive`, `--ring`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```
::

::fw{when="react"}
Install `@goopui/react` and add its stylesheet as shown on the [Installation](/docs/getting-started/installation#nextjs) page, then import the parts from `@goopui/react`. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--accent`, `--destructive`, `--ring`, `--radius`).
::

## Behavior

- **Bloom from the pointer.** A context menu has no button to grow out of, so it grows out of the spot you clicked: the menu pools from a droplet at the pointer, spreads with a lobed edge, overshoots, and wobbles to rest (`wobble`, `openSlosh`). Then it splashes drops all around (`openDrips`). A menu that flips to the left of or above the pointer near the screen edge grows from its corner nearest the pointer.
- **Highlight.** The highlighted item's background is a goo blob. It glides between items with a stretch and a neck, overshoots when it lands, and follows the keyboard as well as the pointer (`highlight`, `momentum`, `wobble`). Its swell leans toward the pointer with a little lag (`followPointer`).

::fw
#vue
- **Select.** Choosing an item squishes the blob (`pop`), then the menu closes once the pop has played. `event.preventDefault()` in your `@select` still keeps it open.

#react
- **Select.** Choosing an item squishes the blob (`pop`), then the menu closes once the pop has played. `onSelect={(e) => e.preventDefault()}` still keeps it open.
::

- **Submenus.** A submenu blooms out of its parent item and has its own highlight (`submenus`). Engine props you leave unset on `GoopContextMenuSubContent` are inherited from the parent menu.
- **Close.** The menu pulls in, wobbles, and shrinks back to the point it grew from (`closeSlosh`).
- **Content stays sharp.** The menu's background, ring, and shadow are drawn on an `aria-hidden` surface behind the items, so the text is never filtered.

## Bloom origin

`bloomFrom` picks where the bloom starts: `'pointer'` (the default: the right-click or long-press point; a submenu blooms from its item) or `'center'` (the panel's own center, like Dropdown Menu).

::fw
#vue
```vue
<GoopContextMenuContent>...</GoopContextMenuContent>                      <!-- from the pointer -->
<GoopContextMenuContent bloom-from="center">...</GoopContextMenuContent>  <!-- from its center -->
```

#react
```tsx
<GoopContextMenuContent>...</GoopContextMenuContent>                     {/* from the pointer */}
<GoopContextMenuContent bloomFrom="center">...</GoopContextMenuContent>  {/* from its center */}
```
::

## Surface color

The trigger is an area, not a button, so the menu defaults to `surface="popover"`: shadcn's popover tokens. `'trigger'` takes the area's colors, and any CSS color works too. Submenus reuse their parent's color.

## Turning parts off

Every effect is its own boolean, and they all default to on:

::fw
#vue
```vue
<GoopContextMenuContent :highlight="false">...</GoopContextMenuContent>   <!-- shadcn's flat highlight -->
<GoopContextMenuContent :pop="false">...</GoopContextMenuContent>         <!-- closes right away -->
<GoopContextMenuContent :submenus="false">...</GoopContextMenuContent>    <!-- plain shadcn submenus -->
<GoopContextMenuContent :open-drips="false">...</GoopContextMenuContent>  <!-- no splash -->
```

`:goo="false"` renders exactly shadcn's `ContextMenuContent`, with its own enter and exit animation.

#react
```tsx
<GoopContextMenuContent highlight={false}>...</GoopContextMenuContent>   {/* shadcn's flat highlight */}
<GoopContextMenuContent pop={false}>...</GoopContextMenuContent>         {/* closes right away */}
<GoopContextMenuContent submenus={false}>...</GoopContextMenuContent>    {/* plain shadcn submenus */}
<GoopContextMenuContent openDrips={false}>...</GoopContextMenuContent>   {/* no splash */}
```

`goo={false}` renders exactly shadcn's `ContextMenuContent`, with its own enter and exit animation.

## Driving it from code

::fw
#vue
`GoopContextMenuContent` and `GoopContextMenuSubContent` expose their engine handle as `handle` and the highlight handle as `highlight` (`null` before they mount, or when that part is off). The menu only exists while open.

#react
On `GoopContextMenuContent` and `GoopContextMenuSubContent`, `ref` is the content element, `goopRef` receives the engine handle, and `highlightRef` receives the highlight handle (`null` before they mount, or when that part is off). The menu only exists while open.
::

## Props

::fw
#vue
The root, trigger, items, labels, groups, separators, and submenu parts take shadcn-vue's props. `GoopContextMenuContent` and `GoopContextMenuSubContent` take reka-ui's props, `class`, and these goo props.

#react
The root, trigger, items, labels, groups, separators, and submenu parts take shadcn/ui's props. The root also takes `sound`. `GoopContextMenuContent` and `GoopContextMenuSubContent` take Radix's props, `className`, and these goo props.

## Accessibility

::fw
#vue
Keyboard navigation, typeahead, focus handling, and ARIA attributes come from reka-ui.

#react
Keyboard navigation, typeahead, focus handling, and ARIA attributes come from Radix.
::

The goo surface and the highlight blob are `aria-hidden` and can't be clicked, and the items are never filtered. Under reduced motion the menu opens and closes plainly: it keeps its goo shape and color, but the bloom, slosh, and splash are off, the highlight snaps between items, and there's no pop. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

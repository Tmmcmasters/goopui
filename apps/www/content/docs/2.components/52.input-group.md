#vue
`GoopInputGroup` has the same parts, markup and classes as shadcn-vue's Input Group: `GoopInputGroupAddon`, `GoopInputGroupButton`, `GoopInputGroupText`, `GoopInputGroupInput` and `GoopInputGroupTextarea`. Swap the imports and you're done.

#react
`GoopInputGroup` has the same parts, markup and classes as shadcn/ui's Input Group: `GoopInputGroupAddon`, `GoopInputGroupButton`, `GoopInputGroupText`, `GoopInputGroupInput` and `GoopInputGroupTextarea`. Swap the imports and you're done.

## Installation

::fw
#vue
Install `@goopui/nuxt` or `@goopui/vue` as shown on the [Button page](/docs/components/button#installation). The Nuxt module auto-imports every `GoopInputGroup*` part.

#react
Install `@goopui/react` and add its stylesheet as shown on the [Installation](/docs/getting-started/installation#nextjs) page, then import the Input Group parts from `@goopui/react`.
::

## Usage

::fw
#vue
```vue
<script setup lang="ts">
const query = ref('')
</script>

<template>
  <GoopInputGroup container-class="max-w-sm">
    <GoopInputGroupInput v-model="query" placeholder="Search..." />
    <GoopInputGroupAddon>
      <SearchIcon />
    </GoopInputGroupAddon>
    <GoopInputGroupAddon align="inline-end">12 results</GoopInputGroupAddon>
  </GoopInputGroup>
</template>
```

#react
```tsx
'use client'
import { GoopInputGroup, GoopInputGroupAddon, GoopInputGroupInput } from '@goopui/react'
import { SearchIcon } from 'lucide-react'
import { useState } from 'react'

export function Search() {
  const [query, setQuery] = useState('')
  return (
    <GoopInputGroup containerClassName="max-w-sm">
      <GoopInputGroupInput value={query} onChange={(e) => setQuery(e.target.value)} placeholder="Search..." />
      <GoopInputGroupAddon>
        <SearchIcon />
      </GoopInputGroupAddon>
      <GoopInputGroupAddon align="inline-end">12 results</GoopInputGroupAddon>
    </GoopInputGroup>
  )
}
```

## What it does

It feels like its parts, with no new effect of its own:

- **The ring is GoopInput's**, drawn around the whole group: when the field inside takes focus, goo flows around the group's border from where you clicked (an addon click too), closes with a wobble, ripples from the caret as you type and drains when focus leaves. `aria-invalid` on any part turns it destructive with a small drip. The props are GoopInput's (`flow`, `ripple`, `wobble`, `drain`, ...).
- **Buttons are GoopButtons.** `GoopInputGroupButton` is a ghost `GoopButton` with its own goo, exactly as it behaves outside the group.
- **The field is plain.** `GoopInputGroupInput` and `GoopInputGroupTextarea` have no ring of their own: the group's ring is theirs.
- **No layout shift.** The goo layer sits in a wrapper (`containerClass` / `containerClassName` sizes it) and paints outside the group's border, never moving anything.
- **Server render.** SSR renders shadcn's markup plus the wrapper; the ring attaches in the browser.

## Props

::component-props{name="input-group"}
::

::fw
#vue
`GoopInputGroup` exposes `handle` (the live ring) and `el` (the group). `GoopInputGroupButton` takes every `GoopButton` prop. Every part takes `class`.

#react
`GoopInputGroup`'s `ref` is the group and `goopRef` receives the live ring handle (an `InputHandle`). `GoopInputGroupButton` takes every `GoopButton` prop. Every part takes `className` and its element's props.
::

## Accessibility

Same as shadcn: a `role="group"` around a real `<input>` or `<textarea>`; label the field (`aria-label` or a `<label>`). The goo layer is `aria-hidden`. Under reduced motion the ring is static. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

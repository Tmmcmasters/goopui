#vue
`GoopItem` has the same parts, markup and classes as shadcn-vue's Item: `GoopItemGroup`, `GoopItemSeparator`, `GoopItemMedia`, `GoopItemContent`, `GoopItemTitle`, `GoopItemDescription`, `GoopItemActions`, `GoopItemHeader` and `GoopItemFooter`. `GoopItem` is a reka-ui `Primitive`, so `as` and `as-child` work (e.g. with `NuxtLink`). Swap the imports and you're done.

#react
`GoopItem` has the same parts, markup and classes as shadcn/ui's Item: `GoopItemGroup`, `GoopItemSeparator`, `GoopItemMedia`, `GoopItemContent`, `GoopItemTitle`, `GoopItemDescription`, `GoopItemActions`, `GoopItemHeader` and `GoopItemFooter`. `GoopItem` takes `asChild` (Radix Slot, e.g. with Next.js `Link`). Swap the imports and you're done. `GoopItem` and `GoopItemGroup` are client components; the other parts render in Server Components.
::

## Usage

::fw
#vue
```vue
<template>
  <GoopItemGroup>
    <GoopItem v-for="p in people" :key="p.email" as-child size="sm">
      <NuxtLink :to="`/people/${p.id}`">
        <GoopItemContent>
          <GoopItemTitle>{{ p.name }}</GoopItemTitle>
          <GoopItemDescription>{{ p.email }}</GoopItemDescription>
        </GoopItemContent>
      </NuxtLink>
    </GoopItem>
  </GoopItemGroup>
</template>
```

#react
```tsx
import { GoopItem, GoopItemContent, GoopItemDescription, GoopItemGroup, GoopItemTitle } from '@goopui/react'
import Link from 'next/link'

export function People({ people }: { people: { id: string; name: string; email: string }[] }) {
  return (
    <GoopItemGroup>
      {people.map((p) => (
        <GoopItem key={p.id} asChild size="sm">
          <Link href={`/people/${p.id}`}>
            <GoopItemContent>
              <GoopItemTitle>{p.name}</GoopItemTitle>
              <GoopItemDescription>{p.email}</GoopItemDescription>
            </GoopItemContent>
          </Link>
        </GoopItem>
      ))}
    </GoopItemGroup>
  )
}
```
::

Set the goo props on `GoopItemGroup`; its items inherit `goo`, `press`, `speed` and `preset` (a prop set on a `GoopItem` wins there).

## What it does

- **One blob in a group.** In a `GoopItemGroup`, hovering a link or button item lights it with a soft goo background in shadcn's muted tone, and the same blob glides to the next item as you move (`momentum`, `wobble`). Keyboard focus moves it too. Plain `<div>` items are never lit, as in shadcn (only links get a hover fill).
- **Press.** Pressing an interactive item squishes it a few pixels and lets it settle with a small jelly bounce, like a `GoopButton` body (`press`). It only ever shrinks, so nothing around it moves. Enter and Space press it too.
- **Outside a group** a link item keeps shadcn's flat hover fill and still has the press.
- **No sticky hover on phones.** Touch never lights an item.
- **Server render.** SSR renders shadcn's markup; the goo attaches in the browser.

## Accessibility

Interactive items are real links or buttons with the shadcn focus ring. List semantics differ a little from shadcn, whose `ItemGroup` is a `role="list"` with no `listitem` children (screen readers and axe flag that):

- **Plain items** (a `<div>`): the group is a `role="list"` and each item is a `role="listitem"`, so screen readers announce "list, 3 items".
- **Link or button items** (`as-child` / `asChild`, an `as="a"` or `as="button"`, or a component like `NuxtLink`): the group has no list role and the items keep their own. A `listitem` role on an `<a>` or `<button>` would replace its link or button role, and a list can only hold `listitem`s, so a group of links is a plain group of real links.
- The group picks while it renders, from its items' props (and bare `<a>` / `<button>` children), so the server markup and the hydrated page match. Wrap an item in your own component and the group can't see it: set `role` yourself then. A `role` you set on the group or an item always wins.
- `GoopItemSeparator` is decorative (`role="none"`), and the blob is `aria-hidden`; neither counts as an item.

Under reduced motion the blob snaps and items don't squish. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

`GoopMenubar` wraps the same [reka-ui Menubar](https://reka-ui.com/docs/components/menubar) primitive as shadcn-vue's Menubar, with the same API. Keyboard navigation across the bar and inside menus, typeahead, focus handling, and positioning work the same. Swap the imports and you're done.

## Installation

### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopMenubar*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--muted`, `--popover`, `--popover-foreground`, `--accent`, `--destructive`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```

## Usage

```vue
<script setup lang="ts">
// Nuxt auto-imports these. In plain Vue, import them:
import {
  GoopMenubar,
  GoopMenubarContent,
  GoopMenubarItem,
  GoopMenubarMenu,
  GoopMenubarSeparator,
  GoopMenubarShortcut,
  GoopMenubarTrigger,
} from '@goopui/vue'
</script>

<template>
  <GoopMenubar>
    <GoopMenubarMenu>
      <GoopMenubarTrigger>File</GoopMenubarTrigger>
      <GoopMenubarContent>
        <GoopMenubarItem>New Tab <GoopMenubarShortcut>⌘T</GoopMenubarShortcut></GoopMenubarItem>
        <GoopMenubarSeparator />
        <GoopMenubarItem>Print...</GoopMenubarItem>
      </GoopMenubarContent>
    </GoopMenubarMenu>
    <GoopMenubarMenu>
      <GoopMenubarTrigger>Edit</GoopMenubarTrigger>
      <GoopMenubarContent>
        <GoopMenubarItem>Undo <GoopMenubarShortcut>⌘Z</GoopMenubarShortcut></GoopMenubarItem>
      </GoopMenubarContent>
    </GoopMenubarMenu>
  </GoopMenubar>
</template>
```

The parts mirror shadcn-vue's: `GoopMenubar`, `Menu`, `Trigger`, `Content`, `Group`, `Label`, `Item` (`inset`, `variant="destructive"`), `CheckboxItem`, `RadioGroup`, `RadioItem`, `Separator`, `Shortcut`, `Sub`, `SubTrigger`, `SubContent`, and `Portal`, each prefixed with `GoopMenubar`. The trigger highlight lives on `GoopMenubar`; each menu's goo lives on `GoopMenubarContent` and `GoopMenubarSubContent`.

## Behavior

- **One body across the bar.** The hover and open background of the triggers is a single goo body. It sits on the trigger you hover or arrow to and flows to the next one with momentum: it stretches, joins its trailing tail with fat, low lumps, and lands with a jelly overshoot (`highlight`, `momentum`, `wobble`). Leaving the bar shrinks it away. While a menu is open it stays on that menu's trigger and follows the open menu as you slide along the bar.
- **Menus bloom.** A menu pools from its center, spreads with a lobed edge, overshoots, and splashes drops all around, kept off the bar (`openSlosh`, `openDrips`). It pulls in and shrinks back on close (`closeSlosh`).
- **Item highlight.** Inside a menu, the highlighted item is a goo blob that glides between items, follows the keyboard, and leans toward the pointer (`highlight`, `followPointer`). Choosing an item squishes it (`pop`), then the menu closes. `event.preventDefault()` in your `@select` still keeps it open.
- **Submenus.** A submenu emerges from its row and has its own highlight (`submenus`).
- **Content stays sharp.** The goo is drawn on `aria-hidden` layers behind the triggers and items, so the text is never filtered.

## Inheritance

Menus inherit the bar's `goo`, `wobble`, `momentum`, `speed`, `preset`, and `renderer` unless they set their own, so one prop sets the whole menubar's feel:

```vue
<GoopMenubar preset="wild">...</GoopMenubar>         <!-- wild bar and menus -->
<GoopMenubar :momentum="false">...</GoopMenubar>     <!-- no stretch anywhere -->
<GoopMenubar :goo="false">...</GoopMenubar>          <!-- plain shadcn Menubar -->
```

Submenus inherit from their parent menu.

## Turning parts off

Every effect is its own boolean, and they all default to on:

```vue
<GoopMenubar :highlight="false">...</GoopMenubar>                <!-- shadcn's flat trigger hover -->
<GoopMenubarContent :highlight="false">...</GoopMenubarContent>  <!-- flat item highlight -->
<GoopMenubarContent :pop="false">...</GoopMenubarContent>        <!-- closes right away -->
<GoopMenubarContent :open-drips="false">...</GoopMenubarContent> <!-- no splash -->
```

`:goo="false"` on a menu renders exactly shadcn's `MenubarContent`, with its own enter animation.

## Driving it from code

`GoopMenubar` exposes the trigger highlight handle as `handle`. `GoopMenubarContent` and `GoopMenubarSubContent` expose their engine handle as `handle` and the item highlight handle as `highlight` (`null` before they mount, or when that part is off).

## Accessibility

Keyboard navigation, typeahead, focus handling, and ARIA attributes come from reka-ui. The goo layers are `aria-hidden` and can't be clicked. A trigger reached with the keyboard gets the goo body, so focus is always visible. Under reduced motion the goo keeps its shape and color, but the bar's body and the item highlight snap between targets, and the menus open and close plainly with no bloom, splash, or pop. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#vue
`GoopPopover` wraps the same [reka-ui Popover](https://reka-ui.com/docs/components/popover) primitive as shadcn-vue's Popover, with the same API. Focus handling, dismissal, and positioning work the same. Swap the imports and you're done.

#react
`GoopPopover` wraps the same [Radix Popover](https://www.radix-ui.com/primitives/docs/components/popover) primitive as shadcn/ui's Popover, with the same API and classes. Focus handling, dismissal, and positioning work the same. Swap the imports and you're done.

## Installation

::fw{when="vue"}
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopPopover*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--primary`, `--foreground`, `--ring`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```
::

::fw{when="react"}
```bash
pnpm add @goopui/react
```

```css [app/globals.css]
@import "tailwindcss";
@import "@goopui/react/goop.css";
```

That one line adds the styles and points Tailwind at the component classes. It works the same in Next.js and Vite; see [Installation](/docs/getting-started/installation#nextjs). It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--popover-foreground`, `--primary`, `--foreground`, `--ring`, `--radius`).

## Usage

::fw
#vue
```vue
<script setup lang="ts">
// Nuxt auto-imports these. In plain Vue, import them:
import {
  GoopButton,
  GoopPopover,
  GoopPopoverContent,
  GoopPopoverDescription,
  GoopPopoverHeader,
  GoopPopoverTitle,
  GoopPopoverTrigger,
} from '@goopui/vue'
</script>

<template>
  <GoopPopover>
    <GoopPopoverTrigger as-child>
      <GoopButton variant="outline">Open popover</GoopButton>
    </GoopPopoverTrigger>
    <GoopPopoverContent>
      <GoopPopoverHeader>
        <GoopPopoverTitle>Dimensions</GoopPopoverTitle>
        <GoopPopoverDescription>Set the dimensions for the layer.</GoopPopoverDescription>
      </GoopPopoverHeader>
    </GoopPopoverContent>
  </GoopPopover>
</template>
```

#react
```tsx
import {
  GoopButton,
  GoopPopover,
  GoopPopoverContent,
  GoopPopoverDescription,
  GoopPopoverHeader,
  GoopPopoverTitle,
  GoopPopoverTrigger,
} from '@goopui/react'

export function Dimensions() {
  return (
    <GoopPopover>
      <GoopPopoverTrigger asChild>
        <GoopButton variant="outline">Open popover</GoopButton>
      </GoopPopoverTrigger>
      <GoopPopoverContent>
        <GoopPopoverHeader>
          <GoopPopoverTitle>Dimensions</GoopPopoverTitle>
          <GoopPopoverDescription>Set the dimensions for the layer.</GoopPopoverDescription>
        </GoopPopoverHeader>
      </GoopPopoverContent>
    </GoopPopover>
  )
}
```
::

The parts are `GoopPopover`, `GoopPopoverTrigger`, `GoopPopoverContent`, `GoopPopoverAnchor`, `GoopPopoverHeader`, `GoopPopoverTitle`, and `GoopPopoverDescription`. All the goo lives on `GoopPopoverContent`.

## Behavior

- **Open (bloom).** A droplet swells at the panel's own center and spreads out in every direction with a lobed edge until it fills the panel. It overshoots and settles with a jelly wobble (`wobble`). `bloomStart="merge"` starts from a few drops that fuse instead of one.
- **Slosh and splash.** Every edge bulges past rest, rebounds, and wobbles (`openSlosh`), each side a little differently (`sloshVariety`). Drops splash off all around, fall, and fade, and none land on the trigger (`openDrips`).
- **Close.** The panel pulls in, wobbles (`closeSlosh`), and shrinks back to its center, faster than it opened.
- **Content stays sharp.** Only the panel's background, ring, and shadow are goo. They're drawn on an `aria-hidden` surface behind your content, so text and inputs are never filtered.
- **Layout** never changes. The goo draws in an overlay with `pointer-events: none`.

## Open styles

::fw
#vue
`flowStyle="bloom"` is the default. Two older opens are still there:

- `flowStyle="neck"`: goo bulges out of the trigger edge that faces the panel, runs across as a thick neck, swells into the panel, and pinches off. Close sucks it back into the trigger.
- `:flow="false"`: a bulb swells at the trigger edge and the panel inflates out of it. The neck stretches and snaps (`bridge`, `momentum`).

#react
`flowStyle="bloom"` is the default. Two older opens are still there:

- `flowStyle="neck"`: goo bulges out of the trigger edge that faces the panel, runs across as a thick neck, swells into the panel, and pinches off. Close sucks it back into the trigger.
- `flow={false}`: a bulb swells at the trigger edge and the panel inflates out of it. The neck stretches and snaps (`bridge`, `momentum`).
::

`bridge` and `momentum` only apply to these two. The bloom ignores them.

::fw
#vue
```vue
<GoopPopoverContent bloom-start="merge">...</GoopPopoverContent>
<GoopPopoverContent flow-style="neck">...</GoopPopoverContent>
<GoopPopoverContent :flow="false">...</GoopPopoverContent>
```

#react
```tsx
<GoopPopoverContent bloomStart="merge">...</GoopPopoverContent>
<GoopPopoverContent flowStyle="neck">...</GoopPopoverContent>
<GoopPopoverContent flow={false}>...</GoopPopoverContent>
```

## Surface color

By default the panel takes the trigger's color: the whole goo (panel, bridge, and drops) uses the trigger's background, and the content uses its text color. If the trigger has no background of its own, the theme's primary is used. Tokens inside the panel (muted text, borders, inputs) are retinted to match.

Set `surface` to change that. `'popover'` uses shadcn's popover tokens, so the panel looks like a normal shadcn popover. Any CSS color works too:

::preview{:controls="false"}
:demo-popover{set="surface"}
::

::fw
#vue
```vue
<GoopPopoverContent>...</GoopPopoverContent>                         <!-- 'trigger' (default) -->
<GoopPopoverContent surface="popover">...</GoopPopoverContent>
<GoopPopoverContent surface="oklch(0.62 0.19 150)">...</GoopPopoverContent>
```

#react
```tsx
<GoopPopoverContent>...</GoopPopoverContent> {/* 'trigger' (default) */}
<GoopPopoverContent surface="popover">...</GoopPopoverContent>
<GoopPopoverContent surface="oklch(0.62 0.19 150)">...</GoopPopoverContent>
```
::

The colors are read again on every open, so a theme or trigger change is picked up.

## Burst knobs

On open, the panel sheds drops. Four numeric props shape the burst. They only matter while `openDrips` is on:

- `openDripAmount` (0 to 3): how many drops.
- `openDripSize` (0.3 to 2.5): how big.
- `openDripFling` (0 to 3): how far they fly.
- `openDripVariety` (0 to 1): the mix of big globs and specks. 0 makes them all alike.

`sloshVariety` (0 to 1, default 1) shapes the slosh instead: how differently each side bulges on open and close (off-centre, one or two lumps, staggered, re-rolled every open). 0 gives an even, centred bulge.

::preview{:controls="false"}
:demo-popover{set="burst"}
::

::fw
#vue
```vue
<GoopPopoverContent :open-drip-amount="2" :open-drip-size="1.6" :open-drip-fling="2" :open-drip-variety="1">
  ...
</GoopPopoverContent>

<GoopPopoverContent :open-drips="false">...</GoopPopoverContent>
```

#react
```tsx
<GoopPopoverContent openDripAmount={2} openDripSize={1.6} openDripFling={2} openDripVariety={1}>
  ...
</GoopPopoverContent>

<GoopPopoverContent openDrips={false}>...</GoopPopoverContent>
```
::

`openSlosh`, `openDrips`, and `closeSlosh` take `true`, `false`, or a strength from 0 to 2.

## Anchoring somewhere else

Put a `GoopPopoverAnchor` around any element and the popover positions against it, and the goo emerges from it, instead of the trigger:

::fw
#vue
```vue
<GoopPopover>
  <GoopPopoverAnchor as-child>
    <div class="rounded-lg border p-3">The goo comes out of this box</div>
  </GoopPopoverAnchor>
  <GoopPopoverTrigger as-child>
    <GoopButton>Open</GoopButton>
  </GoopPopoverTrigger>
  <GoopPopoverContent>...</GoopPopoverContent>
</GoopPopover>
```

#react
```tsx
<GoopPopover>
  <GoopPopoverAnchor asChild>
    <div className="rounded-lg border p-3">The goo comes out of this box</div>

    <GoopButton>Open</GoopButton>
```

## Driving it from code

::fw
#vue
`GoopPopoverContent` exposes its engine handle as `handle` (`null` before it mounts, or when `goo` is off). The panel only exists while open.

#react
`GoopPopoverContent`'s `goopRef` receives its engine handle (`null` before it mounts, or when `goo` is off). The panel only exists while open; `ref` is the panel element, as in shadcn/ui.
::

## Props

::fw
#vue
The root, trigger, anchor, header, title, and description take shadcn-vue's props. `GoopPopoverContent` takes reka-ui's `PopoverContent` props (`side`, `align`, `sideOffset`, `alignOffset`, `collisionPadding`, and the rest), `class`, and these goo props. Defaults are `align="center"` and `sideOffset="4"`, like shadcn.

#react
The root, trigger, anchor, header, title, and description take shadcn/ui's props. `GoopPopoverContent` takes Radix's `PopoverContent` props (`side`, `align`, `sideOffset`, `alignOffset`, `collisionPadding`, and the rest), `className`, `goopRef`, and these goo props. Defaults are `align="center"` and `sideOffset={4}`, like shadcn.

## Accessibility

::fw
#vue
Focus handling, Escape and outside-click dismissal, and ARIA attributes come from reka-ui. The goo surface is `aria-hidden` and can't be clicked, and your content is never filtered. Under reduced motion the popover opens and closes plainly: the panel keeps its goo shape and color, but the bloom, bridge, slosh, drops, and wobble are all turned off. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#react
Focus handling, Escape and outside-click dismissal, and ARIA attributes come from Radix. The goo surface is `aria-hidden` and can't be clicked, and your content is never filtered. Under reduced motion the popover opens and closes plainly: the panel keeps its goo shape and color, but the bloom, bridge, slosh, drops, and wobble are all turned off. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

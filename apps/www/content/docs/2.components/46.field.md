## Usage

::fw
#vue
```vue
<script setup lang="ts">
import { GoopField, GoopFieldDescription, GoopFieldError, GoopFieldLabel, GoopInput } from '@goopui/vue'
import { ref } from 'vue'

const email = ref('')
const error = ref('')
</script>

<template>
  <GoopField :data-invalid="!!error">
    <GoopFieldLabel for="email">Email</GoopFieldLabel>
    <GoopInput id="email" v-model="email" type="email" :aria-invalid="!!error" />
    <GoopFieldDescription>We'll never share it.</GoopFieldDescription>
    <GoopFieldError :errors="error ? [error] : []" />
  </GoopField>
</template>
```

#react
```tsx
import { GoopField, GoopFieldDescription, GoopFieldError, GoopFieldLabel, GoopInput } from '@goopui/react'
import { useState } from 'react'

export function Email() {
  const [email, setEmail] = useState('')
  const [error, setError] = useState('')
  return (
    <GoopField data-invalid={!!error}>
      <GoopFieldLabel htmlFor="email">Email</GoopFieldLabel>
      <GoopInput id="email" value={email} onChange={(e) => setEmail(e.target.value)} type="email" aria-invalid={!!error} />
      <GoopFieldDescription>We'll never share it.</GoopFieldDescription>
      <GoopFieldError errors={error ? [error] : []} />
    </GoopField>
  )
}
```
::

`GoopFieldError` renders nothing without `errors` or content. `errors` takes strings or `{ message }` objects; duplicates are dropped, one message shows as text, several as a list.

## What it does

- **The controls keep their own goo.** A Field is a composite, so it feels like its parts: a `GoopInput` inside keeps its focus ring (and its destructive ring with a drip under `aria-invalid`), a `GoopCheckbox` its fill, a `GoopSwitch` its flood, a `GoopTagsInput` its tags. Field adds no effect of its own around them.
- **drip.** When an error appears, a small drop of the destructive colour hangs off the error's top edge, right under the control where an invalid input's own drip hangs, falls on a thin neck into the first line and spreads flat into it.
- **reveal.** The message unrolls top-down right behind the drop.
- **Gentle.** One small drop, about half a second, then nothing is left behind: the drop's layer exists only while it plays.
- **No layout shift.** The message takes its space at once, as in shadcn; the unroll is a clip on its paint, and the drop is painted outside the layout, so nothing moves and the page's scroll size never changes.
- **Reduced motion.** The message just shows.

Set the goo props on `GoopField` (its error inherits them) or on `GoopFieldError` (they win there).

## Forms

shadcn wraps Field in a form library (vee-validate in Vue, react-hook-form in React). goopUI doesn't ship those wrappers or depend on either library: Field already takes everything they produce. Pass the library's field state to the parts: `data-invalid` on `GoopField`, `aria-invalid` on the control, and the library's errors to `GoopFieldError`.

::fw
#vue
With [vee-validate](https://vee-validate.logaretm.com) (`pnpm add vee-validate`):

```vue
<script setup lang="ts">
import { useField, useForm } from 'vee-validate'

const { handleSubmit } = useForm()
const { value: email, errors, handleBlur } = useField<string>('email', (v) =>
  /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v ?? '') || 'Enter a valid email address.',
)
const onSubmit = handleSubmit((values) => console.log(values))
</script>

<template>
  <form @submit="onSubmit">
    <GoopField :data-invalid="errors.length > 0">
      <GoopFieldLabel for="email">Email</GoopFieldLabel>
      <GoopInput id="email" v-model="email" type="email" :aria-invalid="errors.length > 0" @blur="handleBlur" />
      <GoopFieldError :errors="errors" />
    </GoopField>
    <GoopButton type="submit">Subscribe</GoopButton>
  </form>
</template>
```

#react
With [react-hook-form](https://react-hook-form.com) (`pnpm add react-hook-form`):

```tsx
import { GoopButton, GoopField, GoopFieldError, GoopFieldLabel, GoopInput } from '@goopui/react'
import { Controller, useForm } from 'react-hook-form'

export function Subscribe() {
  const form = useForm({ defaultValues: { email: '' } })
  return (
    <form onSubmit={form.handleSubmit((values) => console.log(values))}>
      <Controller
        name="email"
        control={form.control}
        rules={{ pattern: { value: /^[^\s@]+@[^\s@]+\.[^\s@]+$/, message: 'Enter a valid email address.' } }}
        render={({ field, fieldState }) => (
          <GoopField data-invalid={fieldState.invalid}>
            <GoopFieldLabel htmlFor="email">Email</GoopFieldLabel>
            <GoopInput {...field} id="email" type="email" aria-invalid={fieldState.invalid} />
            <GoopFieldError errors={[fieldState.error]} />
          </GoopField>
        )}
      />
      <GoopButton type="submit">Subscribe</GoopButton>
    </form>
  )
}
```
::

Schema validators (zod, valibot, yup) work the same way through the library's resolver: their errors are `{ message }` objects, which `GoopFieldError` takes as they are.

::fw
#vue
`GoopFieldError` also takes `errors` (`(string | { message?: string })[]`) and exposes `handle` (the live `FieldErrorHandle`). `GoopFieldLegend` takes `variant="legend" | "label"`, `GoopFieldLabel` takes `for`; every part takes `class`.

#react
`GoopFieldError` also takes `errors` (`(string | { message?: string })[]`); its `ref` is the message element and `goopRef` receives the live `FieldErrorHandle` (`null` while hidden). `GoopFieldLegend` takes `variant="legend" | "label"`, `GoopFieldLabel` takes `htmlFor`; every part takes `className` and its element's props.
::

## Accessibility

Same markup as shadcn: `GoopField` is a `role="group"`, `GoopFieldError` is a `role="alert"` (announced when it appears), and labels point at their controls. Point the control at its description or error with `aria-describedby` if you like. The drop is `aria-hidden` and never moves under reduced motion. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

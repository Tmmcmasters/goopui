#vue
`GoopCommand` wraps the same [reka-ui Listbox](https://reka-ui.com/docs/components/listbox) primitive as shadcn-vue's Command, with the same API and the same filter: every item registers its text, typing hides items and groups that don't match, and `GoopCommandEmpty` shows when nothing does. Swap the imports and you're done. To filter the items yourself, turn the built-in filter off with [`ignore-filter`](#your-own-filter).

#react
`GoopCommand` wraps [cmdk](https://cmdk.paco.me), the same library as shadcn/ui's Command, with the same API and the same filter: typing scores every item, hides the ones that don't match and sorts the rest, and `GoopCommandEmpty` shows when nothing does. Swap the imports and you're done. To filter the items yourself, turn the built-in filter off with [`ignoreFilter`](#your-own-filter) (cmdk's `shouldFilter={false}`).
::

## Installation

::fw
#vue
### Nuxt

```bash
pnpm add @goopui/nuxt
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@goopui/nuxt'],
})
```

The module auto-imports every `GoopCommand*` part, adds `goop.css`, and points Tailwind at the component classes. It needs Tailwind CSS v4 and the shadcn tokens (`--popover`, `--accent`, `--input`, `--ring`, `--radius`).

### Vue

```bash
pnpm add @goopui/vue
```

```css [main.css]
@import "tailwindcss";
@import "@goopui/vue/goop.css";
```

#react
Install `@goopui/react` and add its stylesheet as shown on the [Installation](/docs/getting-started/installation#nextjs) page, then import the `GoopCommand*` parts from `@goopui/react`. It installs cmdk itself.
::

The parts are `GoopCommand`, `Input`, `List`, `Empty`, `Group`, `Item`, `Separator`, `Shortcut`, and `Dialog`, each prefixed with `GoopCommand`. The goo settings live on `GoopCommand` (or `GoopCommandDialog`), and its parts read them.

## Behavior

- **Highlight.** The active item's background is a goo blob. It glides between items as the arrow keys or the pointer move the highlight, stretches with a neck while it travels, and overshoots a little when it lands (`highlight`, `momentum`, `wobble`). Over a group heading or a separator the trailing goo stays a low, wide mound. The pointer moves the highlight too, like cmdk.
- **Follow the pointer.** As the pointer moves along an item, the blob's swell leans toward it with a little lag (`followPointer`). From the keyboard it stays centred.
- **Filter.** When typing hides the highlighted item, the blob shrinks out and grows in again on the first match.
- **Choose.** Choosing an item squishes the blob (`pop`).
- **Search ring.** The search box gets GoopInput's goo focus ring: it flows around the box from where you clicked, ripples as you type, and drains on blur (`ring`).

## Dialog

`GoopCommandDialog` is shadcn's CommandDialog: a dialog with a screen-reader title and description around a command. It blooms open like [Dialog](/docs/components/dialog): it pools from its center, overshoots every side, and splashes all around, then shrinks back on close.

It takes the dialog's bloom props (`openSlosh`, `openDrips`, `closeSlosh`, `overlay`, ...) and the command's toggles below. `goo`, `wobble`, `speed`, `preset`, and `renderer` drive both. `title` and `description` default to shadcn's.

## Your own filter

::fw
#vue
The built-in filter shows items whose text contains the search. For fuzzy matching, ranking, or results from a server, set `ignore-filter` (reka-ui's Combobox name; cmdk's `shouldFilter={false}`) and render only the items you want, in the order you want. Every item and group renders as given, `GoopCommandEmpty` shows when there are no items, and the highlight still lands on the first result after each keystroke and follows the arrow keys through your order. The site's ⌘K docs search works this way.

```vue
<script setup lang="ts">
const query = ref('')
// Your own matching and ranking (fuzzy, async, ...).
const results = computed(() => rank(pages, query.value))
</script>

<template>
  <GoopCommand ignore-filter>
    <GoopCommandInput v-model="query" placeholder="Search pages..." />
    <GoopCommandList>
      <GoopCommandEmpty>No results found.</GoopCommandEmpty>
      <GoopCommandGroup v-if="results.length" heading="Pages">
        <GoopCommandItem v-for="p in results" :key="p.id" :value="p.id" @select="go(p)">
          {{ p.title }}
        </GoopCommandItem>
      </GoopCommandGroup>
    </GoopCommandList>
  </GoopCommand>
</template>
```

`GoopCommandDialog` takes `ignore-filter` too and passes it to its command.

#react
cmdk's built-in filter scores and sorts the items. For your own matching, ranking, or results from a server, set `ignoreFilter` (cmdk's `shouldFilter={false}`) and render only the items you want, in the order you want. Every item and group renders as given, `GoopCommandEmpty` shows when there are no items, and the highlight still lands on the first result after each keystroke and follows the arrow keys through your order.

```tsx
const [query, setQuery] = useState('')
// Your own matching and ranking (fuzzy, async, ...).
const results = rank(pages, query)

return (
  <GoopCommand ignoreFilter>
    <GoopCommandInput value={query} onValueChange={setQuery} placeholder="Search pages..." />
    <GoopCommandList>
      <GoopCommandEmpty>No results found.</GoopCommandEmpty>
      {results.length ? (
        <GoopCommandGroup heading="Pages">
          {results.map((p) => (
            <GoopCommandItem key={p.id} value={p.id} onSelect={() => go(p)}>
              {p.title}
            </GoopCommandItem>
          ))}
        </GoopCommandGroup>
      ) : null}
    </GoopCommandList>
  </GoopCommand>
)
```

`GoopCommandDialog` takes `ignoreFilter` too and passes it to its command.

## Turning parts off

Every effect is its own boolean, and they all default to on:

::fw
#vue
```vue
<GoopCommand :highlight="false">...</GoopCommand>        <!-- shadcn's flat highlight -->
<GoopCommand :ring="false">...</GoopCommand>             <!-- no goo ring on the search -->
<GoopCommand :follow-pointer="false">...</GoopCommand>   <!-- the blob stays centred -->
<GoopCommandDialog :open-drips="false">...</GoopCommandDialog>  <!-- no splash -->
```

#react
```tsx
<GoopCommand highlight={false}>...</GoopCommand>        {/* shadcn's flat highlight */}
<GoopCommand ring={false}>...</GoopCommand>             {/* no goo ring on the search */}
<GoopCommand followPointer={false}>...</GoopCommand>    {/* the blob stays centred */}
<GoopCommandDialog openDrips={false}>...</GoopCommandDialog>  {/* no splash */}
```
::

`GoopCommandInput` also takes GoopInput's ring props (`flow`, `ripple`, `drain`, ...) and its own `goo` switch.

## Plain shadcn

::fw
#vue
`:goo="false"` renders exactly shadcn's Command:

```vue
<GoopCommand :goo="false">...</GoopCommand>
```

#react
`goo={false}` renders exactly shadcn's Command:

```tsx
<GoopCommand goo={false}>...</GoopCommand>
```

## Props

::fw
#vue
`GoopCommand` takes reka-ui's `ListboxRoot` props (`modelValue`, `multiple`, `highlightOnHover`, ...), `class`, `ignoreFilter`, and these goo props. The other parts take shadcn-vue's props.

#react
`GoopCommand` takes cmdk's `Command` props (`value`, `onValueChange`, `filter`, `loop`, `disablePointerSelection`, ...), `className`, `ignoreFilter`, and these goo props. The other parts take shadcn/ui's props (cmdk's). `GoopCommandList` takes `goopRef` for the highlight's `MenuHighlightHandle`, `GoopCommandInput` for the ring's `InputHandle`.

## Accessibility

::fw
#vue
Keyboard navigation, `aria-activedescendant` on the search box, and the listbox roles come from reka-ui. The highlight blob and the ring are `aria-hidden` and can't be clicked, and the items are never filtered. Under reduced motion the highlight snaps between items with no pop, the ring is static, and the dialog opens plainly. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

#react
Keyboard navigation, `aria-activedescendant` on the search box, and the listbox roles come from cmdk. The highlight blob and the ring are `aria-hidden` and can't be clicked. Under reduced motion the highlight snaps between items with no pop, the ring is static, and the dialog opens plainly. See [Accessibility & reduced motion](/docs/getting-started/accessibility).

## Colors

goopUI uses the shadcn CSS variables you already have. A component's goo is painted in its variant's background token. GoopButton's default variant drips `--primary`, the destructive one drips `--destructive`, and so on. Change those tokens and the goo follows, in light and dark mode.

Under the hood, the engine paints with `--goop-color` (falling back to `currentColor`). The components set it for you. If you use [`@goopui/core`](/docs/core/api) directly, set it yourself:

```css
.my-button {
  --goop-color: var(--primary);
  color: var(--primary-foreground);
  background: transparent; /* the goo body paints the fill */
}
```

## Presets

Start from a preset, then adjust single variables. `playful` is the default. `subtle` is calm enough for a dense dashboard: one slow drip, small reactions, no flying goo. `wild` is for hero sections: bigger and faster, with splashes that escape across the page, gloss, puddles, and long taffy.

```css
.dashboard { --goop-preset: subtle; }
.hero { --goop-preset: wild; }
```

In JS it's `preset: 'wild'`. A preset only changes defaults, so anything you set explicitly still wins. This is everything the presets change:

## Features

Every feature can be switched on or off by itself. A JS option takes `true`, `false`, or a strength; the CSS variable takes the strength, and `0` turns it off.

| Feature | Option | CSS variable | Default |
| --- | --- | --- | --- |
| Hover and tap drips | `drips` | `--goop-drip-count` | on |
| Click shockwave | `shockwave` | `--goop-shockwave` | on |
| Fast hits | `hitEffect` | `--goop-hit-effect` | `shockwave` |
| Splashes reach | `splash` | `--goop-splash` | `near` |
| Wet gloss | `gloss` | `--goop-gloss` | off |
| Taffy pull | `taffy` | `--goop-taffy` | on |
| Reach toward the pointer | `reach` | `--goop-reach` | on |
| Splash strands | `strands` | `--goop-strands` | on |
| Puddles | `puddles` | `--goop-puddles` | off |
| Label ride | `labelRide` | `--goop-label-ride` | on for `[data-goop-label]` content |
| Keyboard squish | `keyboard` | `--goop-keyboard` | on |
| Idle breathing | `idle` | `--goop-idle` | on |
| Oil finish | `finish` | `--goop-finish` | `solid` |

### Hit effects

A fast pointer hit is a hard entry, or a fast swipe across or out of the element. `--goop-hit-effect` decides what it does:

- `shockwave` (default): the same effect as a click, aimed along the motion and scaled by speed.
- `splash`: goo punches out of the far side.
- `both`, or `none`.

### Splash reach

`--goop-splash` decides where shockwave and splash particles go: `near` keeps them within about 70px of the element, `escape` flies them across the page in one shared overlay, and `off` has none. Click or swipe hard across the hero on the [home page](/) to see `escape`.

### Oil finish

`--goop-finish: oil` gives the goo a thin-film iridescent sheen, like oil on a puddle. It's light by default; raise `--goop-oil-intensity` for more. It uses the canvas renderer, and you can switch it on and off at runtime with `update({ finish })`. Under reduced motion the sheen holds still.

```css
.crude-oil {
  --goop-color: oklch(0.17 0.01 60);
  --goop-finish: oil;
  --goop-oil-intensity: 0.6;
}
```

## Every variable

Each knob is a CSS custom property. The engine reads them from the element (so they inherit) when it mounts, and again whenever `update()` runs. This table comes straight from the engine's own metadata, so names, defaults, ranges, and descriptions always match:

Values are plain numbers: `6` and `6px` both read as 6. Anything out of range is clamped, so a typo can't break the simulation.

## Scope

Variables cascade like any custom property, so you can scope them however you like:

```css
/* Everywhere */
:root {
  --goop-thickness: 1.4;
}

/* Thicker goo, splashing across the page, in one section */
.hero {
  --goop-preset: wild;
  --goop-softness: 6;
  --goop-drip-size: 9;
}

/* One component, calmer */
.settings .goop-button {
  --goop-pointer-reaction: 0.4;
  --goop-shockwave: 0;
}
```

The components will also take a few props for the common cases, `goo="sm | md | lg"` and `drip`. Those are planned for v0.1 and shown on the [Button](/docs/components/button) page.

## Precedence

For each knob the engine uses the first one it finds:

1. An option passed in JavaScript (`attachGoop(el, { softness: 6 })`).
2. The `--goop-*` variable on the element, which may be inherited.
3. The preset (`--goop-preset` or `preset`).
4. The built-in default.

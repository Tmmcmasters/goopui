## Colors

goopUI uses the shadcn CSS variables you already have. A component's goo is painted in its variant's background token. GoopButton's default variant drips `--primary`, the destructive one drips `--destructive`, and so on. Change those tokens and the goo follows, in light and dark mode.

Under the hood, the engine paints with `--goop-color` (falling back to `currentColor`). The components set it for you. If you use [`@goopui/core`](/docs/core/api) directly, set it yourself:

```css
.my-button {
  --goop-color: var(--primary);
  color: var(--primary-foreground);
  background: transparent; /* the goo body paints the fill */
}
```

## Goo variables

Every knob is a CSS custom property. The engine reads them from the element (so they inherit) when it mounts, and again whenever `update()` runs. This table comes straight from `@goopui/core`, so the names, defaults, and ranges always match the engine:

:goop-vars-table

Values are plain numbers. `6` and `6px` both read as 6. Anything out of range is clamped, so a typo can't break the simulation. Setting a knob to `0` turns its feature off: `--goop-shockwave: 0`, `--goop-inertia: 0`, and so on.

### Splash modes

A fast entry punches goo out of the far side, and a click sends a shockwave ring. `--goop-splash` decides where those particles go:

- `near` (default): they stay within about 70px of the element, inside its own layer.
- `escape`: they fly across the page in one shared overlay, so they can land anywhere. Try a hard swipe across the hero on the [home page](/).
- `off`: no particles. The edge ripple and the drips still run.

`--goop-oiliness` sets how the particles behave: low is a watery spray, high is slow clumps that stretch into strings.

### Oil finish

`--goop-finish: oil` (or `finish: 'oil'` in JS) gives the goo a thin-film iridescent sheen, like oil on a puddle. It's light by default; push `--goop-oil-intensity` up for more. The finish needs the canvas renderer, and the engine picks it for you when you ask for oil. Because the renderer is chosen when the goo attaches, set the finish up front rather than toggling it later. Under reduced motion the sheen holds still.

```css
.crude-oil {
  --goop-color: oklch(0.17 0.01 60);
  --goop-finish: oil;
  --goop-oil-intensity: 0.6;
}
```

## Scope

Variables cascade like any custom property, so you can scope them however you like:

```css
/* Everywhere */
:root {
  --goop-viscosity: 1.4;
}

/* Thicker goo, splashing across the page, in one section */
.hero {
  --goop-blur: 6;
  --goop-drip-size: 9;
  --goop-splash: escape;
}

/* One component, calmer */
.settings .goop-button {
  --goop-reactivity: 0.4;
  --goop-shockwave: 0;
}
```

The components will also take a few props for the common cases, `goo="sm | md | lg"` and `drip`. Those are planned for v0.1 and shown on the [Button](/docs/components/button) page.

## Precedence

For each knob the engine uses the first one it finds:

1. An option passed in JavaScript (`attachGoop(el, { blur: 6 })`).
2. The `--goop-*` variable on the element, which may be inherited.
3. The built-in default.

## Colors

goopUI uses the shadcn CSS variables you already have. A component's goo is painted in its variant's background token. GoopButton's default variant drips `--primary`, the destructive one drips `--destructive`, and so on. Change those tokens and the goo follows, in light and dark mode.

Under the hood, the engine paints with `--goop-color` (falling back to `currentColor`). The components set it for you. If you use [`@goopui/core`](/docs/core/api) directly, set it yourself:

```css
.my-button {
  --goop-color: var(--primary);
  color: var(--primary-foreground);
  background: transparent; /* the goo body paints the fill */
}
```

## Goo variables

Every knob is a CSS custom property. The engine reads them from the element (so they inherit) when it mounts, and again whenever `update()` runs. This table comes straight from `@goopui/core`, so the defaults and ranges are always current:

Values are plain numbers. `6` and `6px` both read as 6. Anything out of range is clamped, so a typo can't break the simulation.

## Scope

Variables cascade like any custom property, so you can scope them however you like:

```css
/* Everywhere */
:root {
  --goop-viscosity: 1.4;
}

/* Thicker goo in one section */
.hero {
  --goop-blur: 6;
  --goop-drip-size: 9;
}

/* One component */
.danger-zone .goop-button {
  --goop-fall: 60;
}
```

The components will also take a few props for the common cases, `goo="sm | md | lg"` and `drip`. Those are planned for v0.1 and shown on the [Button](/docs/components/button) page.

## Precedence

For each knob the engine uses the first one it finds:

1. An option passed in JavaScript (`attachGoop(el, { blur: 6 })`).
2. The `--goop-*` variable on the element, which may be inherited.
3. The built-in default.

Every goopUI component is also a **shadcn registry item**. The shadcn CLI copies it into your project as plain source, next to your shadcn components, the same way `shadcn add button` does. You own those files and can edit them.

## Two ways to install

::fw
#vue
- **npm** (`@goopui/vue`, `@goopui/nuxt`): you import components from the package and get fixes and new features with `pnpm add @goopui/vue@latest`. See [Installation](/docs/getting-started/installation).
- **shadcn-vue CLI** (this page): the component's `.vue` files land in `components/ui/goop-<name>/`. Change anything you like. Updates don't arrive by themselves: you run `add` again and merge.

#react
- **npm** (`@goopui/react`): you import components from the package and get fixes and new features with `pnpm add @goopui/react@latest`. See [Installation](/docs/getting-started/installation).
- **shadcn CLI** (this page): the component's files land in `components/ui/goop-<name>/`. Change anything you like. Updates don't arrive by themselves: you run `add` again and merge.
::

Either way the goo engine, **`@goopui/core`**, is an npm package. The CLI adds it to your `package.json` as a dependency, and engine updates (physics, renderers, presets) come through npm: `pnpm add @goopui/core@latest`. The copied components only hold the framework glue and the shadcn markup.

## Requirements

::fw
#vue
A Vue 3.5+, Vite or Nuxt app with Tailwind CSS v4 and shadcn-vue set up (`components.json`). If you don't have one yet:

```bash
pnpm dlx shadcn-vue@latest init
```

In Nuxt, `shadcn-vue init` sets up the `shadcn-nuxt` module. It works the same way.

#react
A React 18 or 19 app (Next.js, Vite, ...) with Tailwind CSS v4 and shadcn/ui set up (`components.json`). If you don't have one yet:

```bash
pnpm dlx shadcn@latest init
```
::

## Add a component

::fw
#vue
Pass the component's URL to `add`. Each component page has its command under **Installation**.

```bash
pnpm dlx shadcn-vue@latest add https://goop.timmcmasters.work/r/vue/button.json
```

#react
Pass the component's URL to `add`. Each component page has its command under **Installation**.

```bash
pnpm dlx shadcn@latest add https://goop.timmcmasters.work/r/react/button.json
```
::

That one command adds:

- `components/ui/goop-button/`: the component (here `GoopButton`, its variants and an `index.ts`). goopUI components live in their own `goop-` folders, so they never overwrite a shadcn component of the same name.
- `lib/goop/`: what every goopUI component shares (the goo props, the engine hook, app-wide config, sound). Added once, the first time.
- The goo styles: the rules from goopUI's `goop.css`, merged into your Tailwind CSS file (`app/globals.css`, `src/assets/index.css`, ...).
- npm dependencies: `@goopui/core`, plus what the component needs (`radix-ui`, `cmdk`, `reka-ui`, `embla-carousel-vue`, ...).
- Other goopUI components it builds on: Dialog brings Button, Sidebar brings Sheet, Tooltip and Input.

Then import it from your own folder:

::fw
#vue
```vue
<script setup lang="ts">
import { GoopButton } from '@/components/ui/goop-button'
</script>

<template>
  <GoopButton>Gooey</GoopButton>
</template>
```

#react
```tsx
import { GoopButton } from '@/components/ui/goop-button'

export default function Page() {
  return <GoopButton>Gooey</GoopButton>
}
```
::

The component API is the one on its docs page. App-wide defaults work too, from `lib/goop/config`:

::fw
#vue
```ts [main.ts]
import { GoopPlugin } from '@/lib/goop/config'

app.use(GoopPlugin, { preset: 'subtle' })
```

#react
```tsx [app/layout.tsx]
import { GoopProvider } from '@/lib/goop/config'

// <GoopProvider preset="subtle">{children}</GoopProvider>
```
::

## The @goopui namespace

With a namespace in `components.json` you can write `@goopui/button` instead of the URL:

::fw
#vue
```json [components.json]
{
  "registries": {
    "@goopui": "https://goop.timmcmasters.work/r/vue/{name}.json"
  }
}
```

```bash
pnpm dlx shadcn-vue@latest add @goopui/button @goopui/dialog
```

#react
```json [components.json]
{
  "registries": {
    "@goopui": "https://goop.timmcmasters.work/r/react/{name}.json"
  }
}
```

```bash
pnpm dlx shadcn@latest add @goopui/button @goopui/dialog
```
::

## Browse the registry

The whole catalog is a registry index, so the CLI can list it:

::fw
#vue
```bash
pnpm dlx shadcn-vue@latest list https://goop.timmcmasters.work/r/vue/registry.json
```

#react
```bash
pnpm dlx shadcn@latest list https://goop.timmcmasters.work/r/react/registry.json
```
::

Besides the components, two shared items exist: `goop-lib` (the `lib/goop/` files) and `goop-css` (the styles only). Every component depends on both, so you never add them by hand.

## Updating

- **The engine**: `pnpm add @goopui/core@latest`. This is where most goo behavior lives.
- **A component**: run its `add` command again. The CLI asks before overwriting a file you changed (`--overwrite` skips the question), so commit first and review the diff.
- The registry always serves the components of the latest goopUI release, so a component added today can expect the matching `@goopui/core`. While goopUI is in alpha, `add` pins `@goopui/core` to that exact version. Upgrade the core and re-add the components together.
